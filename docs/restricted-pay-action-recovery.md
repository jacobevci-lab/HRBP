# Restricted pay action receipt recovery
Compensation and payroll client controls verify bounded JSON receipts before presenting success. Compensation submit/approve/reject require the expected change ID/state; APPLY also requires history ID and effective date. Payroll transitions require expected run ID/state and non-sensitive run metadata, with state-specific calculation/approval/payment evidence. Controlled validation failures expose fixed client messages and validated blocker counts. HTML, malformed or oversized bodies, 5xx, timeouts and mismatched receipts become unknown outcomes and are never automatically retried. Controls remain locked until explicit reload. Notification acknowledgement stays best-effort after verified decisions. Server authorization, four-eyes separation, serializable transactions, payroll input fingerprints, audit and durable notifications are unchanged. Action Center compensation/payroll quick paths remain a follow-up.
